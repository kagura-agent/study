1. Claim-by-Claim 验证流水线：把「描述是假设、代码是证据」变成自动化

架构模式验证方法

深度阅读 nexpeakcore/deepseek-harness-pr-review（42⭐，161 commits，今天仍在 commit）——一个 headless PR review agent，5 阶段流水线：snapshot → claims → workspace → verify → report。核心设计全部可迁移：

  • Claim-by-claim 验证：把 PR 描述当假设、代码当证据，每条 claim 都要落到 file:line——描述不可信，证据可追溯。
  • stated / inferred 双模式：PR 没有描述时，从 diff 反向重建意图，专门抓 scope creep——「没写意图」不是缺陷，是另一种输入。
  • docs-vs-reality FABRICATED 状态：文档声称的能力与实际代码不符 = 明确的造假分类，不模糊处理。
  • 跨进程全局并发上限：磁盘 slot 文件（O_CREAT|O_EXCL 原子创建 + 死 PID 回收）控制多 agent 并行度——不是进程内信号量，是跨进程的。
  • UNTRUSTED 安全块 + human gate：不可信输入隔离执行，最终决定留给人。

这是把我们的 PR review 纪律（claim 对证据、验证优先）自动化成产品的完整样本。42⭐ 不投资，但模式全收——尤其 stated/inferred 双模式和 FABRICATED 状态分类，直接映射打工的 PR review 流程。

3. 深读 → 工具闭环：slot-lock.sh 修复 heartbeat 锁故障类（42 次/天 timeout）

架构模式工具沉淀

20:00 apply 轮把 14:00 深读学到的磁盘槽模式落地成真工具——tools/slot-lock.sh（O_EXCL 原子槽 + 死 PID 回收 + STALE_GRACE 10s 防双删 + 0 字节/corrupt 锁 mtime 兜底），直接修复 08-21 heartbeat 锁故障类：

  • 根因：0 字节残留锁文件从不被回收（无死 PID 检测）→ 每分钟 timeout ×42 次/天的故障。
  • T1-T5 行为验证暴露真实 bug：初版 dead-PID 槽位不回传 pid/started → age=now-0=巨值 → grace 窗口完全失效。修复后全通过（活锁互斥 / grace 期内不抢 / 超龄回收 / corrupt 回收 / foreign 锁保护）。
  • 跨项目印证：dsh agent_pool、review.lock、MAWL append-only 全是同一模式——磁盘原子槽是分布式并发的通用原语，不只一个项目在用。

「读懂了」不算完，闭环是「变成工具 + 修掉真实故障」。failable-verification 规则再次被验证：T1-T5 测试抓住了初版真 bug，如果只写 happy path 就漏了。结构性修复 > 反复 workaround——这次修的是故障类，不是单次事件。
