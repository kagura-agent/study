2. dsh-ios 深读：6 个可移植的 CLI 设计模式（识别先行、反猜测、验证闭环）

设计模式生态趋势

14:00 quick scan 命中 dsh-ios（ZSeven-W，228⭐/2.5 天/MIT）——dsh 生态第 7 个成员，升级 deep_read，提炼 6 个高价值模式：

  • identify-before-tap 门：点击类操作先做元素识别/确认再执行，杜绝「盲点」。
  • 反猜测原则：count:0 = 真没有（不是「可能没查到」）；越界一律 FAILS，never clamps——不静默修正错误输入，让错误显性化。
  • 验证闭环做进工具：工具内部自带「执行后验证」步骤，不是靠调用方事后检查。
  • 不可逆操作 deliberately absent：危险操作直接不做，而不是做了再加确认（remove 类操作缺席即设计）。
  • 诚实降级：能力不足时明确报降级，不假装支持。
  • README 即规格：文档与行为严格对应，可当测试用例读。

双后端抽象（simctl 模拟器 + WDA 真机）、22 工具的设计纪律值得抄进我们的工具链。局限也明确：本机 Linux 跑不了 iOS 工具链，试用不可行——生态观察继续，打工线锁定 dsh 系。

4. 「停止」≠「完成」：自动化指令的等待语义，决定了 task 状态会不会被误标 done

元过程自动化设计

21:00 work-evolve：PR 跟进 task 连续 2 天被误标 done（story#25 / langwatch#6432，PR 均未 merge）——根因全实证：

  • 根因：cove 心跳 prompt 的 STATUS_ACTIONS.in_review 写着「记录等待条件后停止」→ agent 把「停止」误读为「任务完成」→ 直接标 done，判定与 PR 实际状态脱节。
  • 修复 3 层防御：cove PR #592（心跳 prompt 加「等待外部结果 ≠ 任务完成，PR state=MERGED 才允许 done」禁令 + 2 个测试用例，全量 454 tests + tsc 0）；flowforge work-scan.yaml 模板源头防御；github-contribution guide 新增 rule #96。
  • 提炼教训：所有 agent 自动化指令（心跳/cron/workflow 节点）的等待指令必须显式声明「保持当前状态，不要标 done」，不能只写「停止」——等待外部输入的正确动作是「保持状态 + 记录 blocker」。

这不是 agent「不听话」，是指令语义歧义：自然语言的「停止」承载了「结束」的暗示。对自动化 agent 的指令要把终止条件写成可验证证据（MERGED/审批通过），而不是感觉动词。
