1. 把开放式 agent loop 放进图，但不要交出图的控制权

控制流边界状态所有权

GoalFlow 的 AgentBaseNode.call() 不是让内层 agent 直接改工作流状态：它把流式回调经 RunnableConfig.configurable 注入，调用受限的 Agent.run()，再要求子类把结果转换成 LangGraph 所拥有的 Command。内层负责产出，图适配层才决定状态更新和下一条边。

  • 开放式推理/工具循环可以存在，但路由、持久化状态和转移条件必须有确定的 owner。
  • 用一个显式 adapter 把“agent 输出”翻译为“工作流命令”，避免工具循环绕过状态机。
  • 这比在 agent 内部隐式修改共享状态更易审计、重试和替换。

教学要点：把 agent 当作受限计算单元；把状态转移当作图的职责。

2. 流式状态必须是请求局部的，并在退出时无条件清理

并发隔离资源生命周期

GoalFlow 用 ContextVar 保存每请求的 _reply_streamed 标记，并在 finally 中 reset。对可能被进程复用的 node 实例，这比把“本轮是否已流式回复”挂在对象字段上更安全：异常、中断或并发请求都不应把状态泄漏给下一轮。

  • 任何跨 await、回调或工具调用保存的临时状态，都要先问：它属于请求、会话还是进程？
  • 请求级状态选 task/context-local 存储；清理放进 finally，不能依赖成功路径。
  • 对流式输出尤其要记录终止与清理，否则重复发送和串台往往只在负载下出现。

教学要点：并发安全不只是“不要共享变量”，而是给状态明确生命周期，并验证失败路径也会回收。

3. 测试受阻时，结论要降级到“已检查的边界”

证据分级测试纪律

本轮在 GoalFlow 本地只收集到 9 个 transformer CLI/路径测试；agent-node 测试在收集阶段因缺少 structlog 停止。这只能证明一部分测试被发现、依赖环境不完整，不能证明 agent 节点通过、失败或达到生产质量。

  • 报告分开写：源代码建立了什么、哪些测试实际运行、哪些因环境未能收集。
  • 不要把“未能运行”填成通过，也不要把依赖缺失归因为项目缺陷。
  • 当验证被阻塞，优先交付可复核的源码边界与复现条件，而不是补一个无根据的总评。

教学要点：可信结论的粒度由证据决定；测试空白本身也应成为显式输出。

4. 技能与 harness 已拥挤：差异化从“能接入”转向“能证明”

生态判断可验证执行

战略扫描中，mattpocock/skills、addyosmani/agent-skills、obra/superpowers 等大型技能仓库与多种 agent harness 同时活跃；同时，社区高信号讨论仍围绕权限、工具调用、评测和长期轨迹调试。信号更像工程整合期，而非“再做一个 skills 目录”就能构成差异化。

  • 新能力要说明：谁授权、实际执行了什么、证据留在哪里、失败时如何恢复。
  • 优先构建可观测的控制面、可复验的评测和明确的能力边界，而非堆叠插件数量。
  • 没有新增机制的重复扫描，应作为方向确认而非强行扩展 backlog。

教学要点：技能正在商品化；可验证的权限、状态和结果，才是更稀缺的产品层。
